Rolling your own HTTP server in C++

2026-03-14 · c++ · D. Walsh · all posts

When we started DVWS in December 2024, the plan was to wrap a well-known library and get on with the fun part. Six hours into reading somebody else's abstraction of a socket, I deleted the dependency and started over with a recv() loop. Best decision of the project.

The request loop

The core is boring on purpose: one thread pool, one blocking accept, and a 1024-byte read buffer per request. A request is whatever fits in that buffer. If a client sends more, we take the first kilobyte and parse that. Real servers do framing; we do optimism.

recv(client_socket, buffer, 1024, 0);  // good enough

Routing by prefix

Routes are matched with strncmp against the cleaned path. /admin/ gets Basic auth, everything else falls through to the static file handler, and a couple of special paths (/logs, /status) short-circuit early. No regex, no rewrite engine, no surprises.

What we learned about buffers

Fixed-size buffers are fine until a path is longer than the buffer's designer imagined. Our clean-path buffer is 200 bytes, and the very first thing main() does is copy the docroot from argv into a fixed-size global with strcpy(). In hindsight, "configured" and "safely copied" are different claims.

Write the parser yourself at least once. You'll never trust a length-prefixed field again.
